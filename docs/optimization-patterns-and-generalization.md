# 当前优化模式、严格条件与泛化路线

> 更新：2026-08-01
> 范围：当前分支 `src/driver/Driver.cpp` 中接入的 `-O1` 流水线，重点覆盖 AArch64。
> 说明：表中的“严格条件”是对当前实现和实验记录的语义级概括，不替代源码中的逐条合法性检查。

## 1. 阅读口径

- 本文以当前 `Driver.cpp` 的实际接线为准；实验记录中已经撤回的 B/C/D/E 候选，以及源码存在但当前未接入 O1 的 pass，不作为现行能力列入主表。
- “针对的模式”描述可复用的程序结构，例如矩阵归约、连续向量循环、递归调用、纯 helper 调用或 producer/consumer 循环，而不是某个样例的名字。
- “严格条件”记录当前实现为了保证语义和目标成本而设置的收紧点。它们是当前命中率偏低、泛化性不足的主要来源。
- 单类样例只定义测量重点，不是匹配条件，也不要求其他样例汇编逐字不变。只要同一通用变换合法地影响其他程序，并且没有明确目标回归，就应记录并评估，而不是因为“其他样例变了”而丢弃。

## 2. 当前优化总表

### 2.1 标量、SSA 与整数语义

| 当前优化 | 模式归类 | 当前收紧的严格条件 |
|---|---|---|
| Mem2Reg、局部标量清理、冗余 load/store、DCE、空块清理 | SSA/标量替换/死代码 | 地址不逃逸；定义、使用、支配和内存效果可解析；删除的值、Store 或块不能有可观察副作用；不改变异常、除零、非法移位和 i32 回绕语义。 |
| 常量折叠、CSE、重复 load/store 消除 | 常量传播/值编号/局部数据流 | 操作必须是无陷阱整数运算，或已证明除数非零、移位在位宽内；相同值要求 SSA 身份或完整内存效果等价；调用、未知写入和别名不确定时回退。 |
| `DivRemPairStrengthReductionPass`、`RemainderComparisonPass` | 除余配对/余数比较强度削弱 | 通常要求同一基本块或可证明支配关系；被除数和除数 SSA 等价；二次幂除数、符号截断、`INT_MIN` 和回绕边界必须可证明；商先于余数、跨块或除数不安全时不改写。 |
| `PowerOfTwoDispatchPass`、`BoundedModuloReductionPass` | 分派归一化/有界余数 | 当前偏好完整连续分派、范围外 fallback、合法动态移位和已证明的非负/有界区间；不能推测执行非法移位、除零或 `INT_MIN / -1`；不满足区间时保留原 CFG。 |
| `AffineModularRecurrencePass`、`NestedInvariantReductionPass` | 计数仿射闭式/嵌套归约 | 循环通常要求唯一预头、回边和退出，计数器零起点单位步长，递推体无未知副作用；步长、模数和累计值必须是循环不变量；带模路径须证明不发生新增溢出，失败时走原循环。 |
| `WidenedModularMultiplyPass` | 递归模乘闭式 | 当前限定为可识别的直接递归模乘形状、整数参数、正且有界模数、可证明的运行时输入范围；宽乘和余数恢复必须落在 i64 安全范围，其他递归形状完整 fallback。 |
| `BitwiseIdiomRecognitionPass` | 位运算递推闭式 | 当前识别规范 radix-2 逐位循环，要求 `%2`、`/2`、单位权重、零累加器、完整 `00/01/10/11` 真值表及有限计数；NAND、提前退出、额外副作用和非规范条件拒绝。 |

### 2.2 函数、调用与递归

| 当前优化 | 模式归类 | 当前收紧的严格条件 |
|---|---|---|
| `FunctionInliningPass` | 小函数内联/调用消除 | 静态调用点、非递归、函数体小、无内部循环或复杂多出口，代码增长和调用者规模在固定预算内；有未知内存效果或预算超限时不内联。晚期内联还要求调用链适合后续状态提升。 |
| `RecursiveInliningPass` | 直接自递归展开 | 返回值函数、直接自递归、完整 CFG/Phi/多返回可克隆；当前展开深度和静态克隆预算固定，`void`、递归形态不完整或代码增长过大时回退。 |
| `TailRecursionEliminationPass` | 尾递归转循环 | 必须是直接尾调用，递归调用结果直接返回，参数更新和基例结构可识别；递归前后不能夹杂可观察副作用、非尾调用或复杂返回合并。 |
| `ConstantArgumentPropagationPass` | 全程序常量传播/调用点特化 | 当前要求所有直接调用点对同一整数形参形成一致常量，或来自已证明不可写的全局；动态实参、不同常量、可写/逃逸对象整体回退。 |
| `RecursiveMemoizationPass` | 分支递归记忆化 | 返回 i32、参数数量和类型受限、至少两个直接自递归调用；完整调用链需证明无外部写入和未知副作用；缓存键必须包含全部整数参数，冲突和生命周期必须安全。读取外部只读上下文时还要求上下文初始化、支配和不变性证明。 |
| `GlobalScalarLocalizationPass` | 循环内全局标量缓存 | 只能缓存可精确解析的标量 GlobalObject；地址不得逃逸；循环内调用必须有可证明的 read-only/read-write 效果；未知调用前刷新、调用后重载，寄存器压力过大时回退。 |

### 2.3 循环、归纳变量与跨迭代数据流

| 当前优化 | 模式归类 | 当前收紧的严格条件 |
|---|---|---|
| `LoopInvariantCodeMotionPass` | LICM/循环不变量外提 | 自然循环、支配关系和唯一安全外提点可解析；指令无陷阱或已证明可安全推测；地址和内存读必须被别名/调用效果证明为循环不变。 |
| `LoopUnrollAndJamPass` | 归约展开、unroll-and-jam、向量累加 | 规范嵌套循环、单位步长、单一归约、无未知调用/写入；数组 GEP 的跨 lane 访问必须证明不别名；AArch64 当前使用固定 32 lane 向量状态，RISC-V 使用压力安全的固定标量因子；尾部和零趟保留。 |
| `CrossLoopStoreForwardingPass`、`AdjacentProducerConsumerLoopFusionPass` | producer/consumer 转发、循环融合 | 两个循环通常相邻、零起点、单位步长、边界相同；producer 对目标只写一次，consumer 只读同一元素；无额外调用、外部 Store、逃逸指针或未知依赖；融合只复制纯 SSA 依赖切片。 |
| `LoopCarriedStoreToLoadForwardingPass` | 跨迭代 Store-to-Load forwarding | 单体规范循环、单一回边、恰当 Store/Load、同一 GEP 根和固定前缀；当前只接受 `iv+C-1` 到 `iv+C` 的单位距离，不能有调用、额外 Store、变化行号或不确定别名；零趟必须有独立 guard。 |
| `LoopScalarPromotionPass` | 循环标量替换/寄存器驻留 | 目标地址循环外定义，循环内访问次数和更新形态受限；同对象其他访问必须能由完整 GEP、归纳关系和别名证明排除；入口 load、循环 Phi、出口一次 Store，复杂出口或调用回退。 |
| `MonotonicContinueEliminationPass`、`MonotonicLoopBoundPass` | 单调后缀删除/循环上界收紧 | 归纳变量通常从零按一递增；continue 后缀只能包含无副作用自增；阈值和上界必须是循环不变量，退出块/Phi 用途必须可证明；动态边界、非单位步长和额外副作用保留原循环。 |
| `IdempotentIterationCollapsePass` | 幂等迭代折叠 | 需要证明状态变换满足 `F(F(S))=F(S)`；当前偏好只写不读、完整覆盖或完整复制种子后调用纯 helper 的结构；输入输出别名、部分复制、条件覆盖和未知调用均回退。 |
| `DeadPrefixIterationEliminationPass` | 倒计数循环最后可观察迭代保留 | 倒计数 IV 只能控制行程；除 IV 外的 Phi 每趟无条件覆盖，旧值不在循环内使用，循环外只观察最后状态；调用链必须只读且无未知副作用；正行程才可夹取到最后一趟。 |

### 2.4 数组、内存效果与需求驱动变换

| 当前优化 | 模式归类 | 当前收紧的严格条件 |
|---|---|---|
| `StackAggregateInitPruningPass` | 局部数组死初始化删除 | 静态一维局部数组不逃逸；入口初始化之后存在由静态边界控制的完整覆盖循环；完整覆盖出口支配后续所有读取，首轮唯一读取只依赖已覆盖元素；覆盖前读取、旁路和额外 Store 回退。 |
| `GuardedInitializationSinkingPass` | 提前返回后的初始化下沉 | 初始化对象不逃逸；存在唯一继续区域支配全部真实访问；入口到继续块的旁路只能返回；只移动纯地址计算和 Store，不改变对象布局或访问顺序。 |
| `DeadGlobalArrayStoreEliminationPass` | 全局数组死写删除 | 对象及所有 `cast/GEP` 派生地址的用途闭包只能是 Store 地址；不能 Load、传参、返回、形成未知 Phi/select 或逃逸；任一未知用途使整个对象回退。 |
| `AffineArrayCopyPropagationPass` | 仿射数组复制传播/布局传播 | 两层循环零起点、单位步长、完整覆盖；源和目标 GEP 必须是可逆的同一归纳变量置换；复制出口支配读取，源在此期间不再被写，目标不逃逸且无别名 Store；局部性不盈利时保留物化布局。 |
| `LazyAffineCopyResolutionPass` | 需求驱动的 last-writer 反向解析 | 调用内核必须是无外部副作用的二维仿射拷贝；目标不逃逸、不被其他函数访问，后续只读取可解析前缀；运行时长度、容量、行宽必须满足保护，否则执行完整拷贝循环。 |
| `ArraySummaryDimensionCollapsePass` | 二维更新降为行摘要/低维状态 | 当前要求二维 i32 对象完整清零或完整初始化、仿射更新、对象互异、最终观察是完整加法归约或不再使用；不能有额外元素读取、别名实参、未知调用或非完整初始化。 |
| `AssociativeChainAggregationPass` | 哈希链聚合/关联归约 | 生产者必须是规范桶链插入，重复键只能更新一个整数节点并维护重复链；消费者先定位桶再执行 i32 加法归约；所有数组根、GEP、局部槽和调用效果须由 IR 对象身份、SSA/use-def、别名/逃逸证明；未知 Store、调用、额外观察和同址等价不完整时回退。 |

### 2.5 矩阵、向量与 AArch64 专用路径

| 当前优化 | 模式归类 | 当前收紧的严格条件 |
|---|---|---|
| `LoopInterchangeRowUpdatePass` | 原地三角矩阵行递推/面板化 | 目标和系数是互异二维 i32 对象；行、列、归约 IV 规范且单位递增；必须保持原地依赖顺序，禁止未知调用、浮点、额外 Store 和目标别名；当前 4×8、2×16 等面板路径只在边界可整除且寄存器预算足够时启用。 |
| `LoopWavefrontColumnPackingPass` | 矩阵 wavefront/列打包 | 必须是可证明依赖顺序的三角更新；已完成列可压缩到不逃逸 scratch；当前按固定列/行块处理，列打包不能改变每个元素的归约顺序；短行、尾部和动态边界回退。 |
| `TriangularTransposeShadowPass` | 转置影子表/跨行局部性 | 外层递减、中层和内层递增的规范三角 CFG；外层体无条件进入中层，所有正常路径必须经过 commit 或零趟 mirror；目标 Store/Call 和额外矩阵写入受限；影子尺寸从已证明数组类型和边界得到，旁路或提前 break 回退。 |
| `AArch64IntegerDotReductionPass`、`StoreProducerReductionFusionPass` | NEON 整数点积、生产写回与平方归约融合 | 只读连续流或已证明的生产 SCC；向量 accumulator 独立、无调用和未知写入；系数/源/目标 GEP 连续且不别名；平方归约、写回顺序和 i32 模回绕必须等价；尾部、零趟和不整除宽度走标量路径。 |
| `AArch64PureMapRecurrenceVectorizationPass` | 有序递推中的纯映射 SLP/NEON | 循环只有可识别 induction 和 state recurrence；被并行的 DAG 只依赖 induction、无内存/调用/未知副作用；四 lane 的包装、signed compare、回绕和原 state 更新顺序逐 lane 保留；动态步长、动态除数和额外 Phi 回退。 |
| `AArch64VectorConstantRemainderPass` | 连续数组余数向量化 | 当前只接受连续 i32 load、固定常量余数、原址 Store 的规范循环；除数、符号修正和 reciprocal 序列必须可证明，负起点、短尾、非单位步长和其他除数回退。固定除数是当前明显的泛化瓶颈。 |

### 2.6 AArch64 Machine IR、汇编与寄存器层

| 当前优化 | 模式归类 | 当前收紧的严格条件 |
|---|---|---|
| AArch64 `MADD/MSUB` 移位加减降级 | 指令选择/强度削弱 | 乘数必须是合法的 `±2^k` 立即数，类型为 i32/i64 且移位合法；模 `2^w` 语义和源/目标寄存器关系必须保持，其他常数保留原 MADD/MSUB。 |
| `AddressReassociation`、`MachineLoopStrengthReduction` | GEP 重关联/指针归纳 | 基址和步长循环不变；归纳变量、GEP scale、Phi 入边和所有使用可解析；当前只放宽少数嵌套循环和小步长，超过函数/候选规模或可能增加寄存器压力时回退。 |
| `CompareBranchFusion`、AArch64 指令合并 | compare+branch/select 合并 | 比较结果单用途、条件码生存区间无冲突、目标/源寄存器和 NZCV 使用安全；只能合并语义等价且不改变 fall-through、异常和控制流的形态。 |
| Machine block placement、loop layout、machine DCE | CFG 布局/机器死代码 | CFG 边和指令语义不变；只在静态控制转移或不可达指令严格减少时调整；入口、调用约定、分支目标和显式终结必须保留。 |
| StackObjectPromotion、图着色寄存器分配、AArch64 零 Store 合并 | 栈对象提升/寄存器分配/访存合并 | 栈对象不逃逸、对齐和对象边界可证明；寄存器颜色、调用保存、spill、scratch 和 ABI 必须安全；零 Store 合并要求连续地址、i32 零值、16 字节对齐和完整 32 字节区间。 |

## 3. 当前泛化性不足的共同原因

从上表可以看到，当前限制大致集中在八类，而不是某个单独 pass 的偶然问题：

1. **CFG 形状过于固定**：大量规则要求唯一预头、唯一回边、单体循环、单一出口或固定的块顺序；等价的 `break`、`continue`、多个出口、循环旋转和空桥接块容易被拒绝。
2. **对象访问要求“全覆盖、单对象、无别名”**：只要数组有部分覆盖、多个消费者、参数别名或行指针逃逸，当前实现通常整体回退，即使其中一部分区域仍然可证明安全。
3. **把“无调用”作为效果证明的替代品**：很多循环直接拒绝任何调用，而不是使用 `readnone`、`readonly`、精确 `mod/ref` 和调用边界刷新。
4. **固定宽度和固定常量过多**：4/8/16/32 lane、K8×J32、固定余数等是目标成本特化，但若进入匹配条件就会缩小结构覆盖面。
5. **范围和溢出证明仍偏局部**：许多规则只接受静态常量或简单正数，尚未统一使用符号区间、模环区间、路径谓词和运行时 guard。
6. **内存证明粒度偏粗**：按整个 GlobalObject 或整个数组回退，缺少 MemorySSA、分片对象、区间别名和元素级 last-writer 证明。
7. **缓存生命周期模型窄**：记忆化通常要求单一上下文、完整参数键和固定 direct-map 容量；跨阶段状态变化、epoch、递归 SCC 和部分可失效缓存尚未统一处理。
8. **分析与成本模型耦合不足**：有些规则为了安全把候选数量压到一个，有些规则为了隔离要求其他汇编不变；这会同时损失泛化性和可组合性。真正应该限制的是代码尺寸、寄存器压力、动态访存和 A53 关键路径成本。

## 4. 在不降低合规性的前提下增强泛化

### 4.1 先补共享证明基础设施

| 现状收紧点 | 建议的通用证明层 | 可放宽的约束 | 必须保留的安全边界 |
|---|---|---|---|
| 只认唯一预头/单回边 | 循环规范化 + LoopInfo/SCEV 风格摘要，统一识别 header、latch、退出集合和归纳关系 | 支持循环旋转、多个退出、`break/continue`、空桥接块和可证明等价的多回边 | 每条退出边的状态语义、零趟/单趟行为和所有 Phi incoming 必须重建并验证。 |
| 看到调用就回退 | 函数效果摘要：`readnone`、`readonly`、精确读写对象集合、调用前后 clobber 集 | 允许纯 helper、只读 helper、只写不相关输出和可刷新的状态调用 | 未知调用、指针逃逸、volatile/外部 ABI 效果必须仍是硬屏障；缓存值在调用边界刷新或失效。 |
| 整个数组/全局对象整体回退 | MemorySSA + 对象分片/区间访问摘要 + GEP 区间关系 | 只对未逃逸切片、独立行/列、非重叠区间或单个元素应用变换 | 任一可观察别名、部分覆盖前读取或不确定地址必须保留原路径；优先生成运行时别名 guard。 |
| 固定常量和固定向量宽度 | 将常量作为 SSA 不变量，将宽度作为目标成本模型参数 | 任意安全正模数、任意合法 lane 宽度、动态边界和尾部；固定 4/8/16/32 仅作为 lowering 选择 | 不能把常量值、数组尺寸或样例身份用于触发；非法移位、除零、回绕和尾部必须有精确 fallback。 |
| 静态范围不足就放弃 | 分层区间分析：有符号区间、无符号区间、模 `2^w` 区间、路径谓词、乘法/除法关系 | 把常量边界放宽到循环不变量、调用摘要和运行时 guard；允许“证明 fast path + 原循环 fallback” | guard 必须覆盖所有可能溢出、除零、移位越界和终止性边界，不能借助未定义行为。 |
| 只能完整融合或完全不融合 | 依赖图、需求切片和观察点分析 | 支持部分循环融合、部分 producer/consumer 转发、多消费者中只融合安全子图 | 保留剩余原循环和原写入顺序；对每个被删除的内存事件给出 last-writer/visibility 证明。 |
| 记忆化只支持单上下文 | 缓存键、epoch、状态版本和失效摘要 | 支持多个稳定上下文、可证明阶段切换、部分状态键和递归 SCC 共享缓存 | 任何影响结果的对象都必须进入键或失效条件；碰撞必须逐字段复核，容量不足必须精确回退。 |
| 变换数量固定为一个 | 候选独立性和增量成本模型 | 同一函数/模块多个互不依赖候选，或多个样例被同一通用变换影响 | 用代码增长、寄存器压力、栈帧、动态访存和目标关键路径限制总预算，不用“只能一个”代替成本模型。 |

### 4.2 按优化类别的具体泛化路线

1. **矩阵和向量**：把“静态整除、固定 tile、固定 lane”改成“动态边界 + 主循环宽度选择 + 标量尾部”。先用 dependence distance 和对象区间证明可交换，再用运行时不别名 guard 处理指针参数。AArch64 可按 A53 成本模型在 4/8/16/32 之间选择，不把宽度写进合法性匹配器。
2. **递归和内联**：把“直接自递归、固定深度、固定参数数量”拆成三个层次：调用图/SCC 识别、效果摘要、代码增长与热度成本。先支持互递归和多返回的通用 CFG 克隆，再用 profile-independent 的结构成本（循环深度、调用边数量、静态增长、寄存器压力）控制是否展开。记忆化则把“单上下文”扩展成参数键 + 只读上下文版本号，任何写入都触发失效而不是整体禁用。
3. **数组复制和 producer/consumer**：把完整覆盖证明改成区域化证明。对每个观察点反向追踪 last writer，只替换可证明的切片；未证明的元素继续执行原代码。这样可支持部分转置、多个消费者和不连续但可分析的 GEP，而不需要把整个对象视为不可优化。
4. **循环归纳和闭式化**：把唯一回边/单一 Phi 改为归纳关系摘要。对每条回边维护状态函数、步长、单调性和溢出区间，使用路径谓词生成 fast path；无法证明的边仍汇入原循环。闭式化只需要证明观察值等价，不必要求整个循环体完全纯净。
5. **哈希链和关联归约**：把当前“i32 加法 + 特定重复链”抽象为带单位元的 `MonoidSummary`：操作、单位元、结合性、交换性、溢出域和观察点都来自 IR 语义。对链节点按对象区间和 key equality 建立依赖图，先聚合独立子链，再处理有别名风险的节点；未知函数仍作为屏障。
6. **内存缓存和标量驻留**：把“无调用”改成对象级 mod/ref。循环内只读对象可长期驻留，写对象按 Store/Call 刷新；对多个标量使用寄存器压力与动态访问次数估算净收益。这样既提高命中率，也避免一次性缓存过多值导致 callee-saved/spill 退化。
7. **AArch64 后端**：让 Machine IR 携带结构化的地址、循环、向量和效果摘要，所有 lowering 消费摘要而不是生成标签或最终汇编文本。对同一语义模式允许多个等价 lowering，由目标成本模型选择，避免把某个固定寄存器、固定向量宽度或固定块布局误当成合法性条件。

## 5. 建议的实现优先级

### P0：共享基础设施

1. 完整的循环摘要：归纳变量、步长、边界、回边集合、退出状态和零趟语义。
2. 对象级 `mod/ref`、MemorySSA/别名区间和调用效果摘要。
3. 统一的 `FastPath + Guard + OriginalFallback` 改写接口，自动维护 Phi、异常边和观察点。
4. 统一成本模型：动态循环次数、load/store、调用、寄存器活跃区间、spill、代码尺寸和 A53 指令/缓存代价。

### P1：最容易扩大命中率的规则

1. `AArch64VectorConstantRemainderPass`：固定除数改为任意安全常量或循环不变量，向量宽度和尾部统一参数化。
2. `LoopCarriedStoreToLoadForwardingPass`：从固定 `C-1/C` 扩展到可证明的有限距离依赖和多维 GEP 前缀。
3. `FunctionInliningPass`、`RecursiveInliningPass`：从“无循环/固定深度”扩展到效果摘要 + 结构成本预算。
4. `AffineArrayCopyPropagationPass`、`LazyAffineCopyResolutionPass`：从完整对象扩展到需求切片和多个观察点。
5. `LoopScalarPromotionPass`、`GlobalScalarLocalizationPass`：从无调用扩展到精确只读/只写调用边界。

### P2：需要更强分析的规则

1. 三角矩阵影子表、wavefront 和 row-panel：引入区域级依赖图，支持多出口、部分 tile 和动态块大小。
2. 递归/循环记忆化：引入 epoch/失效摘要、SCC 级键和容量成本模型。
3. 关联哈希链聚合：从特定链布局提升为通用 monoid/对象依赖分析。
4. 多个 AArch64 向量候选组合：建立跨 pass 的向量状态和寄存器预算，避免一个 pass 破坏另一个 pass 的可识别结构。

## 6. 泛化后的验收要求

泛化不是简单删除 `if` 条件。每次放宽约束都应补充：

- 改名、改维度、改循环上下界、多个出口、`break/continue`、零趟和单趟结构；
- 正负数、`INT_MIN/MAX`、i32 回绕、除零/非法移位和动态边界；
- 指针别名、部分覆盖、数组逃逸、只读/只写/未知调用和跨调用状态变化；
- 主循环、尾循环、标量 fallback 与运行时 guard 的逐路径对拍；
- 所有 60 项性能和必要的 140 项 correctness；
- 所有发生汇编变化的程序，记录直接命中或下游连锁原因、静态/动态开销及官方 Cortex-A53 结果。逐字不变只作为归因证据，不作为禁止变化的条件。

最终目标是：把当前“只有极少数规范形状才命中”的规则，提升为“对一类可证明的语义区域生成快速路径，对其余区域保留原路径”的分层变换。这样既能扩大泛化范围，也不会通过样例名、固定规模、输入特征或不完整证明换取命中率。
